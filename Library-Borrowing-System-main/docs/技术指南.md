# nacon7 图书管理系统技术指南

## 1. 项目概述

### 1.1 项目定位

本项目是一个基于 **Spring Boot** 构建的图书管理系统，提供完整的用户注册、登录、认证、授权、图书管理和借阅管理功能。系统采用前后端分离架构，后端提供 REST API，前端使用 Vue 3 + Vite 构建 Web 客户端。

### 1.2 技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| Java | 21 | 编程语言（含虚拟线程） |
| Spring Boot | 3.2.0 | 应用框架 |
| Spring Security | 6.x | 安全框架 |
| Spring Data JPA | 3.2.x | 数据访问 |
| Spring Cache + Redis | 7.x | 缓存 |
| JWT (JJWT) | 0.12.3 | 令牌认证 |
| MySQL | 8.x | 数据库 |
| Vue | 3.4.x | 前端框架 |
| Vite | 5.2.x | 前端构建工具 |
| TailwindCSS | 3.4.x | CSS 框架 |
| Redis | 7.x | 缓存 + 限流 |
| Docker / Docker Compose | - | 容器化部署 |
| Lombok | 1.18.30 | POJO 简化 |

## 3. 核心流程详解

### 3.1 用户注册流程

```
POST /api/users/register
├─ 接收 RegisterRequest (username, password, phone)
├─ 参数校验 (@NotBlank, @Size)
├─ 检查用户名是否已存在
├─ 检查手机号是否已存在
├─ BCrypt 加密密码
├─ 保存用户到数据库（默认角色 USER）
└─ 返回 UserDTO
```

### 3.2 用户登录流程

```
POST /api/users/login
├─ 接收 LoginRequest (account, password, captchaKey, captcha)
├─ 参数校验 (@NotBlank, @Size)
├─ 验证验证码（Lua 脚本原子校验，防止并发重复使用）
├─ 检查账号是否被锁定（连续5次失败，锁定5分钟）
├─ 根据 account 查询用户（仅支持 username）
├─ BCrypt 密码匹配校验
├─ 登录失败：记录失败次数，累计5次锁定账号
├─ 登录成功：清除失败记录，JWT 生成令牌（含 userId、username）
└─ 返回 LoginResponse (id, username, email, phone, token, role)
```

### 3.3 JWT 认证流程

```
请求到达 → JwtAuthenticationFilter
              ├─ 提取 Authorization Header 中的 Bearer Token
              ├─ 验证 Token 有效性（过期、签名）
              ├─ 解析 Token 获取 username 和 userId
              ├─ 加载 UserDetails（含角色权限）
              ├─ 设置 SecurityContext 认证信息
              └─ 继续过滤器链 → Controller
```

### 3.4 前端请求拦截流程（Axios）

```
前端调用 API → axios 请求拦截器
                 ├─ 从 localStorage 获取 Token
                 ├─ 设置 Authorization: Bearer {token} 请求头
                 ├─ Token 过期时自动跳转登录页
                 └─ 发送请求到后端
```

### 3.5 权限控制流程

```
Controller 方法标注 @PreAuthorize
    ├─ hasRole('ADMIN')         → 仅管理员可访问
    ├─ isAuthenticated()        → 登录用户可访问
    ├─ #username == authentication.name  → 仅本人可访问
    └─ @userServiceImpl.isOwnUser(#id)  → 仅本人可访问
```

### 3.6 验证码流程

```
GET /api/users/captcha
├─ 生成 SpecCaptcha 验证码（130x48，4位字符）
├─ 生成 UUID 作为 captchaKey
├─ 将验证码文本缓存到 Redis（有效期60秒）
└─ 返回 { captchaKey, image: base64编码 }

POST /api/users/login (验证码校验)
├─ 使用 Lua 脚本原子校验验证码
├─ 返回 -1=过期, 0=错误, 1=成功且已删除
└─ 校验成功后继续登录流程
```

### 3.7 图书借阅流程

```
POST /api/book-records/borrow
├─ 接收 BorrowRequest (bookId, borrowDays)
├─ 从 SecurityContextHolder 获取当前登录用户名
├─ 根据用户名查询用户信息（获取 userId）
├─ 检查图书是否存在
├─ 检查图书库存是否充足
├─ 检查用户是否已借阅该图书
├─ 扣减图书库存
├─ 创建借阅记录（设置借阅时间、应还时间，默认30天）
└─ 返回 BorrowRecordDTO
```

> **安全设计**：借阅接口不再接受客户端传入的 `userId`，改为从当前 JWT Token 中解析用户身份，彻底消除越权风险。

### 3.8 图书归还流程

```
POST /api/book-records/return/{recordId}
├─ 根据 recordId 查询借阅记录
├─ 检查记录是否处于借阅状态
├─ 查询图书信息
├─ 增加图书库存
├─ 更新借阅记录（设置归还时间、状态改为已归还）
└─ 返回 BorrowRecordDTO
```

### 3.9 续借流程

```
POST /api/book-records/renew/{recordId}
├─ 根据 recordId 查询借阅记录
├─ 检查记录是否处于借阅状态
├─ 检查续借次数是否已达上限（最多2次）
├─ 延长应还时间（+30天）
├─ 续借次数+1
└─ 返回 BorrowRecordDTO
```

## 5. 安全机制

### 5.1 Spring Security 配置

```java
// 核心配置要点
- CSRF: 禁用（前后端分离场景）
- Session: 无状态（STATELESS）
- 白名单: /api/users/register, /api/users/login, /api/users/captcha, /api/users/captcha/verify, /actuator/**
- 过滤器链: JwtAuthenticationFilter → UsernamePasswordAuthenticationFilter
- 方法级权限: @EnableMethodSecurity 启用 @PreAuthorize
```

### 5.2 JWT 令牌

**Token 结构：**
```
Header: {"alg": "HS256", "typ": "JWT"}
Payload: {
  "sub": "username",
  "userId": 1,
  "username": "zhangsan",
  "iat": 1704067200,
  "exp": 1704153600
}
Signature: HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)
```

**配置参数：**
- `jwt.secret`: 签名密钥（默认: mySecretKeyForJwtTokenMustBeLongEnough123456，支持环境变量覆盖）
- `jwt.expire`: 过期时间（默认: 86400000ms = 24小时，支持环境变量覆盖）

**密钥安全：**
- 使用 `Keys.hmacShaKeyFor()` 生成安全密钥
- 密钥长度不足32字节时自动填充至32字节

### 5.3 密码加密

使用 **BCryptPasswordEncoder** 进行密码哈希：
- 自动加盐
- 单向加密，不可解密
- 每次加密结果不同，但验证时可匹配
- 统一通过 `PasswordUtil` 工具类调用

### 5.4 方法级权限控制

| 注解 | 作用 | 示例 |
|------|------|------|
| `@PreAuthorize("hasRole('ADMIN')")` | 仅管理员可访问 | 删除用户、创建图书 |
| `@PreAuthorize("isAuthenticated()")` | 已登录用户可访问 | 获取个人信息、借阅图书 |
| `@PreAuthorize("#username == authentication.name")` | 仅本人可访问 | 获取个人详情 |
| `@PreAuthorize("@userServiceImpl.isOwnUser(#id)")` | 仅本人可访问 | 获取个人详情 |

> **借阅接口权限**：`borrowBook` 方法标注 `@PreAuthorize("isAuthenticated()")`，任何登录用户均可借阅。用户身份（userId）不再由客户端传入，而是通过 `SecurityContextHolder` 从 JWT Token 解析，确保数据安全。

### 5.5 登录防暴力破解

使用 `LoginAttemptService` + Redis 实现登录限流：

```
LoginAttemptService
    ├─ isExceeded(username, ip)   → 检查是否超过最大尝试次数（5次）
    ├─ incrementAttempts(username, ip) → 增加失败次数，5分钟过期
    └─ resetAttempts(username, ip) → 登录成功时清除失败记录
```

### 5.6 验证码机制

### 5.10 软删除与归档系统

采用 **归档表模式** 实现软删除，而非传统的 `deleted` 字段标记：

```
删除流程：
    ├─ 删除用户/图书
    ├─ 将数据保存到对应归档表（UserArchive/BookArchive）
    ├─ 删除原表记录
    └─ 归档表记录保留删除时间和状态

恢复流程：
    ├─ 从归档表查询记录
    ├─ 删除归档记录（再次删除时可重新归档）
    ├─ 将数据恢复到原表
    └─ 返回恢复后的实体
```

**归档表结构：**

| 归档表 | 对应原表 | 额外字段 |
|--------|----------|----------|
| `t_user_archive` | `t_user` | deleteTime, status |
| `t_book_archive` | `t_book` | deleteTime, status |

**状态字段：**
- `DELETED`: 已删除（默认）
- 恢复时直接删除归档记录，再次删除时可重新归档

**清理机制：**
- 提供 `cleanExpired` 接口，清理指定天数前的归档记录
- 默认保留 30 天，超过后可手动清理

### 5.11 API 限流机制

使用 **Token Bucket（令牌桶）** 算法实现 API 限流，基于 Redis 实现分布式限流：

```
RateLimitFilter (限流过滤器)
    ├─ 第一层：IP全局限流（100次/60秒）
    ├─ 第二层：接口级限流（可配置每个接口不同的限流策略）
    └─ 第三层：用户级限流（200次/60秒）

TokenBucketService (令牌桶服务)
    ├─ tryAcquire(key) → 使用默认限流配置
    └─ tryAcquire(key, capacity, refillSeconds) → 使用自定义配置
```

**限流流程：**
```
请求到达 → RateLimitFilter
             ├─ 获取客户端 IP（支持 X-Forwarded-For）
             ├─ 检查 IP 全局限流
             ├─ 检查接口级限流（登录、注册、验证码等）
             ├─ 检查用户级限流（需认证）
             └─ 通过 → 继续处理
```

**限流配置（application.yml）：**
```yaml
rate-limit:
  global:
    capacity: 100          # 全局令牌桶容量
    refill-seconds: 60     # 补充时间窗口
  user:
    capacity: 200          # 用户级令牌桶容量
    refill-seconds: 60
  endpoints:
    login:
      capacity: 5          # 登录接口限流（5次/60秒）
      refill-seconds: 60
    register:
      capacity: 10         # 注册接口限流（10次/3600秒）
      refill-seconds: 3600
    captcha:
      capacity: 60         # 验证码接口限流（60次/60秒）
      refill-seconds: 60
```

**核心类：**
- `RateLimitFilter` — 限流过滤器（OncePerRequestFilter）
- `RateLimitProperties` — 限流配置属性（@ConfigurationProperties）
- `TokenBucketService` — 令牌桶服务
- `RateLimitException` — 限流异常（HTTP 429）

**过滤器链顺序：**
```
RateLimitFilter → UsernamePasswordAuthenticationFilter → JwtAuthenticationFilter
（限流在最前面，所有请求先经过限流检查）
```

### 5.12 异步非阻塞编程架构

项目通过 Spring `@Async` + 自定义线程池 + Redis 进度查询实现异步任务处理，解决批量操作阻塞请求和 N+1 查询性能问题。

#### 异步线程池配置

```java
// AsyncConfig.java
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean("asyncExecutor")
    public Executor asyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(200);
        executor.setThreadNamePrefix("async-import-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(60);
        return executor;
    }
}
```

#### 异步批量导入架构

```
┌─────────────┐    POST /batch-import-async     ┌──────────────────┐
│   前端 Vue   │ ──────────────────────────────► │  BookController  │
│             │                                  │                  │
│ BookManage  │   立即返回 { taskId }            │  生成 UUID      │
│  View.vue   │ ◄────────────────────────────── │  保存文件 bytes │
│             │                                  │  调用 @Async 方法│
└──────┬──────┘                                  └────────┬─────────┘
       │                                                  │
       │ GET /batch-import/progress/{taskId}              │ @Async("asyncExecutor")
       │ (每 2s 轮询)                                     ▼
       │                                        ┌──────────────────┐
       │                                        │  BookServiceImpl  │
       │                                        │                  │
       │                                        │  1. Redis 写入进度 │
       │                                        │  2. 解析 Excel    │
       │                                        │  3. 事务批量写入  │
       │                                        │  4. Redis 写结果  │
       │                                        └────────┬─────────┘
       │                                                  │
       ▼                                                  ▼
┌─────────────┐                                  ┌──────────────────┐
│   Redis     │                                  │    MySQL          │
│             │                                  │                  │
│ import:     │                                  │  t_book_temp     │
│ progress:   │                                  │  (临时表)         │
│ {taskId}    │                                  │      ↓           │
│ = 状态文本   │                                  │  INSERT...SELECT │
└─────────────┘                                  │  LEFT JOIN 去重  │
                                                 └──────────────────┘
```

#### N+1 查询优化

借阅记录查询采用"两次批量查询 + 内存组装"模式，将 2N 次 SQL 降为 2 次：

```java
// BookRecordServiceImpl.assembleWithBatchQuery()
List<Long> bookIds = records.stream().map(BorrowRecord::getBookId).distinct().collect();
List<Long> userIds = records.stream().map(BorrowRecord::getUserId).distinct().collect();

Map<Long, Book> bookMap = bookRepository.findAllById(bookIds).stream()
        .collect(Collectors.toMap(Book::getId, b -> b));
Map<Long, User> userMap = userRepository.findAllById(userIds).stream()
        .collect(Collectors.toMap(User::getId, u -> u));
```

#### 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 异步方式 | `@Async` + 自定义线程池 | Spring 原生支持，配置简单 |
| 事务管理 | `TransactionTemplate` | `@Async` 与 `@Transactional` 代理冲突，编程式事务更可控 |
| 批量写入 | 临时表 + `INSERT...SELECT` | 利用数据库批量插入优化 + LEFT JOIN 去重 |
| 进度存储 | Redis（10分钟过期） | 高并发读写，自动过期清理 |
| 拒绝策略 | `CallerRunsPolicy` | 任务不丢失，由调用线程兜底执行 |

### 6.5 数据库表结构

CREATE TABLE t_user (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(100) NOT NULL,
    email VARCHAR(100),
    phone VARCHAR(11) NOT NULL UNIQUE,
    role VARCHAR(20) NOT NULL DEFAULT 'USER',
    create_time DATETIME
);

CREATE TABLE t_book (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    author VARCHAR(100) NOT NULL,
    isbn VARCHAR(20) UNIQUE,
    publisher VARCHAR(100),
    publish_date DATETIME,
    category VARCHAR(50),
    description TEXT,
    stock INT NOT NULL,
    available INT NOT NULL,
    create_time DATETIME
);

CREATE TABLE t_borrow_record (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    book_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    borrow_time DATETIME NOT NULL,
    due_time DATETIME NOT NULL,
    return_time DATETIME,
    renew_count INT NOT NULL DEFAULT 0,
    status VARCHAR(20) NOT NULL DEFAULT 'BORROWED',
    FOREIGN KEY (book_id) REFERENCES t_book(id),
    FOREIGN KEY (user_id) REFERENCES t_user(id)
);

## 9. 开发规范

### 9.1 模块依赖规则

- **controller** 类必须放在 `server` 模块，不能放在 `common` 模块
- **common** 模块只能包含 entities、DTOs 和 utility classes
- **server** 模块必须使用 `${project.version}` 依赖 `common` 模块

### 9.2 POM 规范

- 根 `pom.xml` 只包含 `dependencyManagement` 用于版本控制，不包含 `dependencies`
- **common** 模块需要 `jakarta.persistence-api` 依赖用于实体类
- **server** 模块需要 `spring-boot-starter-web` 和 `spring-boot-starter-validation` 依赖
- **client** 模块需要 `spring-boot-starter-web` 依赖防止启动后立即退出
- **client** 模块移除 Nacos Discovery 依赖，使用 Feign 直接 URL 调用

### 9.3 Feign 配置规范

- 客户端使用实例级拦截器（`UserFeignConfig`）管理 Token
- Feign 客户端使用 `url` 属性直连服务端，不依赖服务发现
- Token 通过 `TokenStore` Bean 管理，非静态方法

### 9.4 新增功能开发规范

新增功能遵循以下实现顺序：
1. Entity（实体类）→ common 模块
2. DTO（数据传输对象）→ common 模块
3. Repository（数据访问层）→ server 模块
4. Service（业务逻辑接口）→ server 模块
5. ServiceImpl（业务逻辑实现）→ server 模块
6. Controller（REST API）→ server 模块
